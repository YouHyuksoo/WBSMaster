# 기능추적표 jisung-ui DataGrid 전환

## 범위

- 첫 전환 화면: `/dashboard/process-verification`.
- 14개 컬럼과 기존 적용·상태 변경, 수정 모달, 삭제 확인을 연결했다.
- 정렬·컬럼 필터·너비/순서 조절·고정·페이지 이동·전체화면은 공용 DataGrid를 사용한다.
- 정보카드와 통계 접기 기능은 제거된 상태를 유지한다.
- 다른 업무 목록과 WBS 계층형 화면은 이번 첫 전환에 포함하지 않았다.

## 패키지

- 원본: `C:/Project/jisung-ui`의 `@jisung/ui` 2.9.0. 원본 저장소는 수정하지 않았다.
- 설치 파일: `vendor/jisung-ui-2.9.0-wbs.1.tgz`. 원본 라이브러리 구현은 그대로이며 DataGrid 직접 export와 Next.js 16 호환 범위만 패키지 메타데이터에 추가했다.
- 재생성: `node scripts/package-jisung-ui.mjs C:/Project/jisung-ui`.
- 무결성 해시는 `vendor/jisung-ui-manifest.json`에 기록한다.
- Next.js가 패키지 소스를 변환하며 Tailwind는 패키지의 클래스도 스캔한다. 전역 테마 CSS는 가져오지 않는다.
- 라이브러리의 정규표현식 지원에 맞춰 TypeScript target을 ES2017에서 ES2018로 조정했다.

## 검증

- 가상 데이터 단위 검사: 적용 기본값, 체크/상태 콜백, 수정/삭제 콜백, 정렬 후 ID 일치, 선택형 필터, 페이지 이동과 검색 시 첫 페이지 복귀.
- EGO Lite 실제 화면: 25건 가상 데이터로 페이지 이동·컬럼 검색·적용/상태 변경·수정 모달·삭제 확인·다크모드·전체화면을 확인했다.
- 브라우저 쓰기 요청은 해당 탭의 가상 응답으로 대체했다. 실제 데이터베이스 등록·수정·삭제는 하지 않았다.
- TypeScript 전체 검사 통과. 변경 컴포넌트 ESLint 오류·경고 없음. npm ci dry-run 통과.
- 운영 배포와 프로덕션 빌드는 수행하지 않았다. 실행 중인 개발 서버와 공유하는 `.next`를 덮어쓰지 않았다.
- npm 설치 감사가 저장소 전체 취약점 234건을 보고했다. 이번 설치 전의 동일 감사 결과를 수집하지 않아 신규 발생 여부는 판정하지 않았다. 자동 수정은 하지 않았다.
- bugfix 프로브에 선택형 부분 일치 사례를 추가했다. ai-env-sync 점검은 기존 환경 충돌 33건으로 종료 코드 1이었으며 환경 설정은 수정하지 않았다.

## 의심 / 프로브 / 결과 / 재발방지

- 의심: 문자열 부분 일치 필터가 `적용`에 `미적용`도 포함할 수 있다.
- 프로브: 선택형 컬럼과 accessorFn을 대조하고 가상 데이터로 실제 공용 그리드의 선택 필터를 실행했다.
- 결과: 적용 필터 검사에서 수정 전 실패를 확인했다. 공통 연결부의 선택형 기본 필터를 equalsString으로 바꿨다.
- 재발방지: 기본 필터를 공통 연결부 한 곳에서 관리하고 위 회귀 검사로 검증한다.
