# 지식관리 승인 문서와 WBS 채팅 연결 결과

- 작업일: 2026-11-10, 한국 시간.
- 상태: 운영 반영, 격리 문서 처리 파이프라인, 실제 WBS 문서 목록 채팅 검증 완료.
- 범위: 사용자 `진행해`에 따른 문서 연동. 앞서 승인된 지성 IDC 반영·서비스 재시작 경로를 재사용했다.
- 이전 업무 레코드 연동 결과: [knowledge-integration-result](2026-11-10-knowledge-integration-result.md). 이번 작업은 업로드 문서 본문과 원본 조회를 추가한다.

## 사용 방법

1. 지식관리의 문서 라이브러리에서 **행성오창V2** 프로젝트를 선택한다. 애플리케이션 소스 프로젝트인 `WBSMaster`와 구분한다.
2. 문서를 업로드하고 추출 결과를 검토한 뒤 승인한다.
3. WBS에서 같은 프로젝트를 선택하고 AI 어시스턴트에 `승인된 지식 문서 목록 보여줘` 또는 문서 내용에 관한 질문을 입력한다.
4. 목록·검색 결과에 문서가 있으면 답변의 원본 링크로 파일을 받는다. 원본 요청마다 WBS 로그인과 프로젝트 권한을 검사한다.

승인 완료된 활성 버전만 대상이다. 업로드만 한 문서, 검토 중 문서, 폐기 문서, 이전 버전, 다른 프로젝트와 공용 문서는 포함하지 않는다. 업로드 문서는 WBS 문서함에 복제하지 않으며, WBS 채팅에서 목록·근거·원본 링크를 조회한다.

## 프로젝트와 보관 위치

- WBS 프로젝트: `38f0613b-3048-48c2-9354-b1dc6c9f1a7d` / `행성오창V2`.
- 지식관리 문서 프로젝트: `wbs_20_jisung-idc-wbsmaster_38f0613b-3048-48c2-9354-b1dc6c9f1a7d`.
- `business_binding`으로 원본 시스템 ID와 WBS 프로젝트 ID를 저장한다. 기존 다른 프로젝트와 충돌하면 연결을 거절한다.
- 이 공간은 문서 전용이며 기존 소스 폴더와 DB를 자동 연결하지 않는다. 다른 WBS 프로젝트는 각각 별도 문서 공간 등록이 필요하다.
- 문서 업로드 시 서버 보관 위치: `D:\AKPData\documents\<지식관리 문서 프로젝트 ID>\<문서 ID>\<버전 ID>\original`.
- 카탈로그: `D:\AKPData\documents.json`. 이번에 만든 행성오창V2 공간의 **승인 문서는 0건**이다. 프로젝트 폴더는 실제 업로드 시 생성된다.

## 구현

- 지식관리 `app/business_documents.py`: 결정적인 프로젝트 매핑, 등록 충돌 검사, 승인 활성 버전 목록·검색·원본 조회.
- `app/business_router.py`: 관리자 인증이 필요한 `/api/business/document-project`, `/documents/list`, `/documents/original`.
- `app/business_records.py`: 기존 업무 검색 결과에 승인 문서의 벡터·키워드 근거를 추가한다. 문서 검색 실패는 degraded 상태로 표시한다.
- `app/documents/indexer.py`, `app/vector_search.py`: 승인 작업의 임베딩 모델 버전을 후보·활성화까지 유지한다.
- WBS `src/lib/knowledge/documents.ts`, `document-links.ts`: 서버 사이의 목록·원본 요청과 WBS 내부 원본 링크 생성. 외부 서버가 보낸 URL을 그대로 쓰지 않는다.
- WBS `/api/knowledge/documents` 및 `/api/knowledge/documents/[documentId]/original`: 로그인과 프로젝트 권한을 확인한다. 원본은 attachment, private/no-store, nosniff, sandbox로 전달하며 관리자 키를 노출하지 않는다.
- 채팅 도구 `list_knowledge_documents`, 기존 `search_knowledge`, 출처·원본 링크 지침을 등록했다. 언어모델 호출 구조는 이번에 변경하지 않았다.

## 실제 화면 확인과 한계

- EGO Lite TaskSpace 80에서 사용자 로그인 상태로 운영 WBS의 `행성오창V2` 채팅을 확인했다.
- 질문: `현재 프로젝트의 지식관리에 업로드되어 승인된 문서 목록을 조회해줘. 있으면 원본 링크도 보여줘. 조회만 해줘.`

- 저장된 도구 이력: `list_knowledge_documents`, 승인된 최신 문서 0건.

- 지식관리 업로드 화면은 이번 작업에서 브라우저로 조작하지 않았다. 문서 전용 프로젝트에 대한 기존 화면의 source 없는 처리와 실제 등록 API를 확인했다.

## 발견 결함: 의심 / 프로브 / 결과 / 재발방지

- **의심:** 문서 승인에 모델 버전 확인이 없고 공유 VectorStore 설정을 참조하여, 승인 후보와 질의가 다른 모델 버전으로 기록될 수 있었다. 도구 등록 검사에는 단독 import만 허용하는 불필요한 문법 가정도 있었다.
- **프로브:** 문서 색인기의 stage/activate/cleanup, VectorStore의 stage/search, main의 모델 버전 변경 지점, 같은 지식 모듈의 import 정규식 검사를 대조했다.
- **결과:** 임베딩 전에 모델 버전을 확인하고 승인 결과에 고정했다. 그래프·벡터 후보와 활성화에 같은 버전을 사용하며, 공유 설정이 바뀌어도 승인 작업의 버전을 유지한다. 후보 정리는 프로젝트·문서·버전·작업 ID에 한정하고 해당 노드의 실제 모델 버전으로 커밋 여부를 검사한다. 등록 검사는 여러 이름의 import를 허용한다.
- **재발방지:** 기존 색인기 검사에 실제 후보의 모델 버전과 공유 설정 변경 뒤 활성화 버전 일치를 검증하는 단언을 추가했다. 문서 승인 전후의 실제 임베딩/Neo4j 파이프라인으로도 확인했다.

## 배포·오류·보관 기록

- 운영 기준 WBS HEAD `29b7f6a`를 유지했다. 로컬의 다른 UI·음성·회의록 변경을 운영에 덮지 않았다. 작업 중 다른 에이전트에 의해 로컬 HEAD가 이동했으며 해당 변경을 되돌리지 않았다.
- 지식관리 main.py는 운영 원본에 문서 서비스 제공자와 기존 업무 라우터의 연결만 추가했다.
- 백업: `D:\Backups\WBSMaster\documents-20261110`. 기존 소스와 `.next.before`를 보관했다.
- 배포 임시 빌드의 `.env.local`은 삭제 확인했다. 기존 WBS·지식관리 서비스만 중지·전환·재시작했고, 다른 포트·대체 서버·주기 작업은 만들지 않았다.
- 최초 Python 실행은 pytest 캐시 권한 경고가 있었고, 이후 cacheprovider를 끈 228개 검사가 정상 통과했다.
- 격리 원격 검증의 SSH 채널은 `TimeoutError`로 대기가 끊겼다. 같은 작업을 재실행하지 않고 서버 결과 파일과 프로세스를 확인하여 6개 검증 완료 및 fixture 0건을 확인했다.
- 브라우저 자동 대기에서 UI에 도구 이름이 표시된다고 가정해 45초 timeout이 발생했다. 현재 화면을 재확인하고 저장된 toolSummary로 실제 도구 호출을 검증했다. 앱 오류는 아니었다.
- 로컬 패키징 과정의 줄바꿈 해시 비교와 운영 도구 배열 위치 가정은 업로드 전에 실패했다. 원본 바이트 해시와 운영 소스를 확인해 패키징을 수정한 뒤 SHA-256 대조를 통과했다.
- 증거: `.knowledge-deploy/documents-20261110/{manifest,activation,live-receipt,pipeline-receipt,browser-receipt}.json`, `chat-document-result.png`. 비밀값은 포함하지 않는다.
