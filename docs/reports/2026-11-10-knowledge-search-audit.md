## 확인된 결함

### 1. 키워드의 고정 점수가 의미 검색 순위를 밀어낸다

- 위치: `C:\Project\ai-knowledge-platform\app\business_documents.py:111`, `:129`.
- 키워드 결과에 고정 `1.0`을 주고 벡터의 cosine 점수와 같은 척도처럼 정렬한다. 두 경로에 공통으로 나온 항목은 최초 의미 점수를 유지한다. 그 결과 키워드에만 나온 항목이 공통 검색 항목보다 높은 점수를 받는다.
- 운영 질의 `제안요청서 2026-0927 기능 요구사항 34건 인터페이스 요구사항 9건 비기능 20건`으로 비교했다. 원시 의미 검색 10개 중 7개가 최종 10개에서 밀렸고 최종 결과의 앞 7개는 키워드 전용 `1.0`, 나머지 3개는 의미 점수였다. 의미 검색의 최고 점수는 약 `0.8633`이었다.
- 어떤 결과가 정답인지 전체 관련성을 채점한 것은 아니다. 확인한 문제는 서로 다른 점수를 직접 비교해 키워드 전용 결과를 일괄 우대한다는 것이다.
- 필요한 조치: 두 검색의 순위를 합치는 방식 등 일관된 결합 기준을 적용하고, 실제 질문·정답 근거로 품질을 비교한다.

### 2. 긴 본문이 경고 없이 6,000자에서 잘린다

- 따라서 시트 뒤쪽 항목으로 검색되더라도 언어모델에 그 내용이 전달되지 않을 수 있다.
- 필요한 조치: 원문을 검색에 적합한 조각으로 나누거나 질의 관련 구간을 전달하고, 범위와 잘림 여부를 정확히 표시한다.

### 3. 같은 페이지·슬라이드의 서로 다른 조각이 하나로 합쳐진다

- 중복 판정 키가 문서·버전·위치 종류·위치 값뿐이고 블록/청크 ID를 포함하지 않는다. 같은 페이지의 내용이 다른 두 조각을 주입한 재현에서 2개 입력이 1개 결과로 줄었다.
- 이는 합성 재현이다. 현재 승인 자료 전체에 실제 동일 위치 다중 조각이 존재한다고 확인한 결과는 아니다.

### 4. 검색 한 경로 실패가 성공한 문서 검색까지 버린다

- 위치: `app/business_documents.py:106`~`:112`, `app/business_records.py:121`~`:127`.
- 의미 검색이 성공한 뒤 키워드 검색만 실패하도록 한 재현에서 문서 검색 함수 전체가 예외를 냈다. 상위 서비스는 문서 검색 결과를 추가하지 않고 `document_search_unavailable`만 반환한다. 의미 검색 실패 시 키워드 검색에 도달하지 못하는 경우도 있다.
- 장애를 degraded로 표시하는 동작은 존재하지만, 정상 경로의 결과를 유지하는 처리가 없다.
- 필요한 조치: 경로별 실패를 구분하여 정상 결과를 보존하고 장애 상태를 함께 전달한다. 운영 장애를 일으키는 실험은 하지 않았다.

## 정상 확인 범위와 한계

- 승인 문서 목록은 6건이었다.
- 운영 검색 API가 반환한 모든 업무·문서·관계 결과는 요청 프로젝트 범위와 일치했다. 해당 정상 요청의 degraded는 빈 목록이었다.
- 현재 WBS 지식·문서 경로 검사 20개 통과. PostgreSQL 통합 검사 5개는 별도 환경 설정 없이 건너뛰었다.
- 현재 Python 업무·문서 연결 검사 26개 통과. 여기에 인증, 다른 프로젝트 차단, 승인·활성 버전 조건 검사가 포함된다.
- 기존 검사가 통과해도 위 네 결함은 잡히지 않았다. 합성 프로브와 운영 read-back을 별도로 수행했다.
- 유료 언어모델 호출, 브라우저 채팅 전송, 운영 장애 유발, 고객 데이터 변경은 하지 않았다. 운영 확인은 기존 지식관리 API·Ollama·Neo4j 읽기와 원문 추출 아티팩트 읽기에 한정했다.
- 이전 실제 채팅 검증에서 복합 질문은 검색 도구 3회, 총 약 70초였다. 이는 과거 확인값이며 이번 점검에서 지연 시간을 새로 측정하거나 호출 횟수를 고정하지 않았다.
