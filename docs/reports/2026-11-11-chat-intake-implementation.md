# AI 채팅 업무 등록 파이프라인 구현·검증 기록

- 작성일: 2026-11-11
- 기준: HEAD `d4453b5` 및 현재 작업 트리. 커밋·푸시·운영 배포 없음.
- 요청: 자유 문서를 분석하고 부족한 정보를 채팅으로 보완한 뒤 인터뷰관리·주간보고·이슈사항·협의요청에 등록.
- 설계: [최초 설계안](../specs/2026-11-11-chat-interview-intake-design.md).

## 구현한 동작

공통 흐름은 `문서/텍스트 → 컬럼별 초안 → 부족한 정보 질문 → 답변 부분 반영 → 등록 확인 → 원자적 등록 → 결과 링크`다. 내용이 충분하면 질문 없이 확인 단계로 간다. 기존 채팅 생성 도구를 선택해도 네 업무의 등록은 같은 루프를 거친다. 수정·삭제와 다른 메뉴의 기존 등록은 유지했다.

| 대상 | 보완·저장 규칙 |
|---|---|
| 인터뷰관리 | 제목·실제 날짜·본문 필요. 대상자·현행·문제점·원하는 결과를 보완. 기술적 제약·궁금한 점도 저장. 날짜 미상은 초안으로 유지 |
| 주간보고 | 보고 대상 주에 포함되는 날짜·실적/계획·제목·내용 필요. 프로젝트 시작일로 프로젝트 주차 계산. 본인 보고서에 항목을 추가하고 보고서 이슈는 기존 내용을 보존해 덧붙임. HTML 문자는 이스케이프. 제출 완료 보고서는 차단 |
| 이슈사항 | 제목·내용·분류 필요. 담당자·기한은 미확인 선택 가능. 담당자는 현재 프로젝트 구성원으로 재검증. 초기 상태는 기존 생성 서비스의 OPEN |
| 협의요청 | 제목·내용·발생 단계·서로 다른 선택지 2개 이상 필요. 선택지는 자료/답변에서만 추출. 담당자·기한 미확인 가능. 초기 상태는 기존 생성 서비스의 DISCUSSING |

주간보고의 진행률·완료 여부가 미확인이면 DB의 필수 컬럼에 맞춰 0%·미완료로 저장하고 비고에 미확인 상태를 기록한다. 이 처리는 최종 확인에도 표시한다. 주간보고는 작성 중으로 저장하며 자동 제출하지 않는다.

## 사용법

1. AI 어시스턴트에서 프로젝트를 선택한다.
2. 문서를 첨부하고 “인터뷰관리에 등록해줘”, “주간보고 작성해줘”, “이슈사항에 등록해줘”, “협의요청으로 등록해줘”처럼 요청한다. 텍스트만 붙여 넣어 요청해도 된다.
3. 부족한 정보 질문에 답한다. 한 답변으로 여러 컬럼을 보완할 수 있다. 선택 정보는 “미확인”, “해당 없음”을 명시할 수 있다.
4. 컬럼별 값·원문 근거를 확인하고 등록 버튼을 누른다. 내용 수정은 같은 입력창에서 답한다.
5. 일반 채팅으로 나가도 초안은 남는다. 새로고침 후 “이어서 작성할 초안”에서 선택해 복구한다. 보류·초안 취소·다시 확인도 지원한다.

엑셀의 기존 일괄 가져오기는 첨부 후 대상 선택에서 태스크·이슈·요구사항을 선택해 사용한다. 기본 선택은 AI 문서 분석이다.

## 저장·파일·동시성

- 신규 모델: `ChatAttachment`, `ChatIntakeDraft`, `ChatIntakeEvent`. 최초 설계의 개별 항목·출처 테이블 대신 항목별 안정된 key와 근거를 초안 JSON에 보관하고 revision·응답 이벤트로 변경 이력을 유지한다.
- 허용 문서: txt·md·docx·텍스트 PDF·xlsx·xls·csv. 파일당 5MB, 요청당 첨부 최대 3개, 문서와 입력 합계 10만 자, 항목 최대 20건. PDF 100쪽, 표 30시트·1만 행·200열 상한. ZIP 압축 해제 크기는 20MB 이하.
- `POST /api/upload`의 `purpose=chat_intake`로 업로드한다. 원본은 `uploads/private/chat`에 보관하고 공개 이미지 라우트의 private 접근도 차단한다. 본인·프로젝트 권한을 검사한 ID 기반 다운로드만 제공한다.
- 원본 해시와 문단·쪽·시트·행 위치를 보존한다. 긴 문서는 모든 청크를 읽고 병합한다. 텍스트를 읽을 수 없는 PDF, 상한 초과, 형식 오류는 성공으로 처리하지 않는다.
- MISSING·CONFLICT·DEFERRED·NOT_APPLICABLE 상태를 구분한다. 모델이 제시한 인용문은 실제 원문과 대조한다. 없는 컬럼은 거부한다. 날짜 값은 연도·월·일의 원문 근거를 검사하고 사용자 답변의 상대 날짜는 한국 날짜 기준으로 변환한다.
- 초안 보관/접근 기간은 활동 후 7일, 확인 제안은 30분이다. NEW 초안은 분석 실패 후 다시 확인으로 재시도할 수 있다. 임대 시각·revision으로 동시 보완 답변과 늦은 응답을 보호한다.
- 확인 시 초안 행과 프로젝트 채번 잠금을 사용한다. 선택한 전체 항목·등록 결과·확인 상태·최종 채팅 결과를 하나의 트랜잭션에 저장한다. 뒤쪽 항목 실패 시 앞쪽 생성과 알림도 롤백한다.
- 이미 등록된 제안을 재요청하면 기존 결과를 반환한다. 동일 제목 기존 자료를 확인 전에 표시하고, 확인 뒤 중복 후보가 바뀌면 재확인을 요구한다. 원본을 삭제하거나 기존 업무 기록을 덮어쓰지 않는다.

## 변경 지점

- `src/lib/chat-intake/`: 업무 정책, 추출, 구조화, 초안, 질문, 업무 연결, 등록·취소.
- `src/app/api/chat/route.ts`, `src/lib/chat-agent/`: 직접 요청과 기존 생성 도구 모두 공통 루프로 연결.
- `src/app/api/chat/intakes/`, `attachments/`: 초안 목록·복구·비공개 원본 조회.
- `src/app/api/chat/actions/[id]/`: 신규 초안 제안은 전용 원자적 등록/취소 서비스 사용.
- `src/app/dashboard/chat/`: 문서 첨부, 초안 선택·질문·근거·확인 패널, 프로젝트 전환 보호.
- 인터뷰·이슈·협의요청 생성 서비스: 수동 입력과 공통 프로젝트 잠금을 공유하도록 연결.
- 의존성: `mammoth`와 `pdf-parse`; 문서 테스트에는 `jszip`. Node 서버 패키지는 Next.js 번들 외부 패키지로 지정.

## DB 적용

- 적용 대상: 로컬 개발 `127.0.0.1:55432/wbsmaster`, `public` 스키마.
- 마이그레이션: `prisma/migrations/20261111120000_chat_intake/migration.sql`.
- 변경: 신규 테이블 3개와 `chat_histories.intakeDraftId` 추가. 기존 업무 행에 대한 갱신·삭제 없음.
- SQL을 트랜잭션으로 적용한 뒤 `prisma migrate resolve --applied 20261111120000_chat_intake`로 적용 이력을 기록했다.
- 운영 DB에는 적용하지 않았다. 운영 배포 전에 같은 마이그레이션 적용이 필요하다.

## 검증 결과

| 검증 | 결과 |
|---|---|
| 관련 단위·회귀 테스트 | 140개 통과. 일반 실행에서는 전용 DB 테스트 15개를 의도적으로 제외하고 아래 실행에서 별도 검증 |
| 실제 PostgreSQL 통합 테스트 | 15개 통과. 네 업무의 질문·보완·등록, 동시 확인, 재전송, 이전 revision, 다른 사용자 접근, 취소·만료, 전체 롤백, 동시 수동 등록, 3건 일괄 코드 중복 검사 |
| 문서 바이트 테스트 | txt·md·docx·텍스트 PDF·xlsx·xls·csv, ZIP 크기 초과, 빈 PDF·잘못된 서명·텍스트 상한 확인 |
| 비공개 파일·권한 | 공개 이미지 경로의 private 접근 및 경로 정규화 우회 차단, 프로젝트 권한 없는 업로드에서 저장 호출 차단 |
| 화면 | EGO Lite의 `localhost:3000/dashboard/chat`에서 네 업무 각각 첨부 ID 전송 → 질문 → draftId·revision을 포함한 답변 → 등록 확인 → 결과 표시 확인. 고정 API 응답을 사용했으며 실제 사용자 업무 데이터를 만들지 않음 |
| 새 모듈 린트 | 통과 |
| 기존 채팅 페이지 린트 | 기존 effect 관련 오류 3개 남음. HEAD에서도 같은 로더 계열 오류가 재현되어 이번 범위에서 수정하지 않음. 기존 확인 API 테스트의 unused 경고도 별도 |
| 프로덕션 빌드·타입 검사 | 최종 `npm run build` 통과 (컴파일·타입 검사·정적 페이지 생성) |

실제 DB 테스트는 `node scripts/test-chat-intake.cjs`로 수행한다. 처음 별도 DB 생성은 권한 부족으로 실패했다. 이후 같은 로컬 DB에 무작위 이름의 전용 스키마를 만들어 전체 테스트 스키마를 설치했다. Prisma 어댑터와 SQL 검색 경로 모두 전용 스키마에 고정하며 종료 시 제거한다. 사용자 프로젝트/업무 테이블은 테스트에 사용하지 않았다.

화면 자동화 도중 전송 버튼의 아이콘을 포함한 이름과 스냅샷 root 지정 때문에 제어 오류가 발생했다. 관찰한 버튼 상태에 맞춰 선택자를 수정한 후 같은 EGO 공간에서 네 업무를 다시 확인했다. 검증 공간은 종료했다. DB 통합 테스트와 화면 테스트를 분리해 수행했으므로 실제 AI 제공자를 통한 한 번의 전체 흐름 검증으로 표현하지 않는다.

## 의심 / 프로브 / 결과 / 재발방지

- **의심:** 화면에는 존재하는 인터뷰 본문 컬럼이 채팅 등록에서 빠지거나, DB 잠금·중복 비교가 단위 목 테스트에서만 정상으로 보일 수 있다.
- **프로브:** Prisma/화면/등록 도구의 5개 본문 컬럼 대조, 프로젝트 잠금 호출 검색, 같은 제안의 동시 실행과 같은 제목이 있는 실제 JSONB 초안 재등록을 전용 PostgreSQL에서 실행했다.
- **결과:** 공통 등록 도구에서 빠진 기술적 제약·궁금한 점을 추가했다. 실제 DB에서 void 잠금 반환형 역직렬화 오류와 JSONB 객체 키 순서에 의존한 중복 비교 오류를 재현하고 수정했다.
- **재발방지:** 인터뷰 5개 본문 필드 포함 테스트, 실제 DB 동시성·재전송·중복 후보·롤백 테스트를 추가했다. 잠금은 정수 반환 쿼리로 통일하고 중복 후보는 정규화된 값 배열로 비교한다. 원래 오류 상태에서 DB 테스트가 실패한 것을 확인했다.

## 확인하지 않은 사항과 남은 운영 작업

- 실제 AI 제공자의 자유 문서 추출 정확도는 고정 응답 테스트로 대체했다. 유료/실서비스 AI 호출은 하지 않았다.
- 운영 DB 변경·배포·운영 화면 확인은 수행하지 않았다.
- 스캔 PDF/이미지 OCR, pptx는 현재 범위에 포함하지 않는다.
- 만료는 접근·재사용을 제한한다. 만료 파일/초안의 물리 삭제 배치와 프로젝트 삭제 뒤 파일 정리는 아직 자동화하지 않았다. 정식 등록 원본의 장기 보관 기간도 운영 정책 결정이 필요하다.
- 지식 전송은 기존 업무 저장 경로/기존 DB 트리거를 사용한다. 이번 테스트에서 외부 지식 서버의 색인·검색까지 확인하지 않았다.
- 패키지 설치가 출력한 저장소 전체 취약 항목은 이번 기능의 추가분과 기존 항목으로 분류하지 않았고 `audit fix`는 실행하지 않았다.

사용자와 다른 도구의 기존/동시 변경을 보존했고, 서버를 새로 시작하거나 사용자가 실행한 서버를 중지하지 않았다.
