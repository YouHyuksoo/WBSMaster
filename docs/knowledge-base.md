## 4. WBS Master 요구사항

### WBS 데이터/화면

- WBS는 엑셀 기준으로 전체 설정되었고, 간트와 상세보기에서 빠른 수정이 가능하도록 기능이 추가됐다.
- WBS Master 웹 화면과 엑셀의 진도율/지연율이 다르게 보이는 이슈가 있었다.
- 일부 엑셀 값은 계산식 기반이므로 웹과 비교할 때 산식 기준을 맞춰야 한다.
- WBS 항목의 산출물은 SharePoint 링크로 연결하는 요구가 있다.
- 마일스톤 항목도 WBS와 함께 업데이트되어야 한다.

### 완료/지연 표시 기준

- WBS에서 `100%`는 완료를 의미한다.
- 완료 여부와 계획 대비 지연일은 별도 개념이다.
- 화면에서는 상태와 지연일을 분리해 보여주는 방향이 반영됐다.
- 상태 예시: 완료, 진행중, 대기.
- 100% 완료된 작업의 지연일 기준: 실제완료일 - 계획완료일.
- 100% 미완료 작업의 지연 판단 기준: 계획완료일과 현재일 비교.

### WBS 지표 산식

- 계획: 말단 업무 각각의 시작일~종료일 대비 오늘 경과비율.
- 실적: 말단 업무 각각의 실제 진행률.
- 지연율: 계획 - 실적. 양수면 지연, 음수면 선행.
- 달성률: `(실적 / 계획) × 100`. 100% 이상이면 목표 달성.
- 주간 추이표를 만들려면 매주 금요일 등 기준일 스냅샷 데이터가 필요하다.

## 5. 주간보고 기능

- 주간보고는 금요일 16시까지 작성하는 운영 기준이 공유됐다.
- 특이사항이 없으면 1장만 작성해도 된다.
- 사용자별 주간보고 관리가 반영됐다.
- 내가 작성하지 않으면 다른 사람 보고서가 보이지 않는 문제가 있었고, 작성 여부와 무관하게 조회 가능하도록 수정 필요가 확인됐다.
- 캐시 때문에 다른 사용자의 보고서가 내 화면에 보이거나 수정 가능한 문제가 있었다.
- 제출 완료 후에는 수정 불가, 제출 취소 후 수정 가능 정책이 정리됐다.
- 삭제 시 확인 컨펌 창을 띄우도록 수정됐다.
- 전주 계획 자동 로딩 기능은 전주에 계획한 일을 금주 보고에서 진행상황으로 이어 쓰기 위한 기능이다.
- 프로젝트 선택이 잘못되면 주차가 다르게 보일 수 있으며, 상단 프로젝트를 `행성 MESV2`로 맞춰야 한다.

## 8. ERP/MES 인터페이스 정책

### 환경 반영 원칙

- 단순 제공 뷰 컬럼 추가는 운영/DEV/TFT에 동시에 반영 가능한 것으로 공유됐다.
- 받는 업무, 프로시저 로직, 프로그램 수정이 필요한 항목은 DEV 테스트 후 PROD 반영이 원칙이다.
- PROD는 이미 다른 법인이 사용 중이므로 테스트 없이 바로 반영하면 안 된다.
- 적용 시점에는 DEV 기준으로 PROD에도 반영 가능하도록 준비해야 한다.

### 창고/로케이터

- 베트남 ERP는 창고와 로케이터를 분리 관리한다.
- 예시: 창고 `110`, 로케이터 `E01`.
- ERP에는 로케이터 ID가 별도 존재한다.
- 작업지시에서 완료창고가 내려올 때 창고와 로케이터를 분리해야 한다.
- `[Ky gui]`는 500번대 고객사 창고로 확인됐다.
- 500번대 창고는 출하 후 재고관리 창고 성격이다.
- `[WH]`는 일반 창고 의미로 보고 `[Ky gui]`와 구분해야 한다.

### 조직/법인 기준

- `ORG` 또는 `OU`는 `ORGANIZATION`의 상위 개념이다.
- 재고 관리는 `ORGANIZATION` 아래 창고가 있으므로 `ORGANIZATION` 기준으로 관리해야 한다.
- MES 내부에서는 `ORGANIZATION_ID`를 관리하고 이 값으로 조회하는 방식이 성능상 유리하다고 판단됐다.
- 인사 모듈은 법인별로 다르며, 해외 법인에는 `ORGANIZATION_CODE`가 없는 경우가 있다.

## 10. 작업지시 상태 및 취소 방지

- 작업지시 상태값으로 `3: 확정`, `4: 생산완료`, `7: 취소`, `12: 마감/Closed`가 논의됐다.
- `XMES_WIP_DISCRETE_JOBS_V`, `XMES_WIP_MTL_REQ_V` 두 뷰에 `12(Closed)`가 추가됐다.
- MES에서 작업지시 START 후 ERP에서 작업지시를 취소하지 못하게 해야 한다.
- ERP는 `xwip_mes_status` 테이블을 체크한다.
- MES는 직접 INSERT가 아니라 `xwip_mes_status_pkg.insert_row` 프로시저 호출 방식으로 상태를 전달해야 한다.

```sql
PROCEDURE insert_row
(
  o_errmsg          OUT NOCOPY VARCHAR2,
  o_errtag          OUT NOCOPY NUMBER,
  p_organization_id IN         NUMBER,
  p_wip_entity_name IN         VARCHAR2,
  p_mes_status      IN         VARCHAR2,
  p_attribute1      IN         VARCHAR2 DEFAULT NULL,
  p_attribute2      IN         VARCHAR2 DEFAULT NULL,
  p_attribute3      IN         VARCHAR2 DEFAULT NULL,
  p_attribute4      IN         VARCHAR2 DEFAULT NULL,
  p_attribute5      IN         VARCHAR2 DEFAULT NULL
);
```

## 11. 품목/자재/입출고 정책

- 품목 유형 기본 코드:
  - `1`: 제품
  - `2`: 반제품
  - `3`: 원자재
  - `4`: 상품
- 스페어파츠의 최종 품목유형 코드는 추가 확인 필요하다.
- 소모품/스페어파트는 비용 처리 대상이며 수불을 타지 않는 것으로 공유됐다.
- `CP1`: 사용 후 잔여물이 남지 않는 소모품. 예: 알코올, 접착제, 접착 테이프.
- `CP2`: 사용 후 잔여물이 남는 소모품. 예: 스텐실, Skinning Knife.
- CP1/CP2는 비용 처리 차이보다 정산 보고서 및 스크랩 처리 관행 차이에 가깝다.

## 12. 기타입출고 정책

- ERP 기타입출고는 입고/출고 구분 없이 모든 항목이 입고와 출고 모두 가능하다.
- 예: `불용 폐기`는 일반적으로 출고 항목이지만, 잘못 입력한 경우 삭제가 불가능해 반대 입고로 `+/- 0` 처리할 수 있다.
- MES UI에서는 사용자 오류를 줄이기 위해 기타입고/기타출고 선 선택 또는 안내가 필요할 수 있다.
- 단, ERP 정책상 항목 자체를 입고/출고로 제한하면 정정 처리가 어려워질 수 있다.

## 14. HNS 외주/입출고 프로세스

### HNS 자재 및 WIP 출고

- 외주팀으로부터 자재 출고 요청 접수.
- 창고에서 요청에 따라 자재 준비.

- 창고에서 자재/WIP 인보이스와 패킹리스트 작성 후 서브콘 FWD 전달.
- FWD가 인보이스로 수입 신고.
- 자재/WIP 출고 데이터는 매일 ERP 업로드.

### 외주에서 Haengsung 입고

- Haengsung이 Subcon에 납품 계획 Request 송부.
- Subcon이 대응 가능 수량 검토 후 회신.
- Haengsung이 수량 Confirm.
- Haengsung이 Subcon에 PO 발행.
- Subcon이 Invoice/Packing List 작성 후 FWD 전달.
- FWD가 세관 신고.
- 통관 완료 후 Subcon에서 Haengsung으로 실물 납품.
- Haengsung이 입고 수량 확인 및 창고 입고 처리.

### 시스템 반영 방향

- 관련 서류는 현재 수기/엑셀로 작성 중이다.
- 우선 MES에서 리스트 출력이 가능하도록 대응하기로 했다.
- ERP/MES 중 어느 시스템에서 작성하는 것이 사용자에게 편리한지 추가 확정이 필요하다.

## 15. 설비 인터페이스

- MES V2 설비 인터페이스 대상 공정/설비 및 업체정보 확인 요청이 있었다.
- 설비 비가동현황 엑셀 관리 템플릿이 공유됐다.
- 설비 인터페이스와 현장 단말기 관련 화상회의가 여러 차례 진행됐다.
- 기존 DLL 설비 인터페이스 방식을 MES V2에서도 유지해야 하는 이슈가 있다.
- TESTOP 장비는 검사 전 유효성 체크만 소켓통신으로 적용하고 설비 알람 모니터링을 제외하면 PLC 개조가 불필요할 수 있다.
- 이 경우 비용 절감 가능성이 있다.

## 16. DISPLAY/PCBA 검사기 및 FCT

- DISPLAY ICT/FCT 현황:
  - ICT: 4대, 제조사 `MEASURENIX`.
  - FCT: 5대, 제조사 `GOOIL ENGINEERING`.
- DISPLAY 사업부 검사기 현황 리스트가 공유됐다.
- 후공정 검사기는 계속 늘어날 예정이며 기능 검사와 외관 검사 자동화가 검토 중이다.
- Auto 다운로드/Verify, TV 화면검사 장비도 MES 연동 대상이다.
- 신규 자화 FCT가 설비 인터페이스 논의 대상에 포함됐다.
- PCBA Manual 4라인 KNS FCT 로그 생성 여부 확인 요청이 있었다.
- 당시 KNS는 개발 중이고 행성 Jig를 사용 중이라고 답변됐다.
- 행성 Jig 및 Final FCT 메저컴에서 LGD 로그 파일이 생성되지 않는 이슈가 있었다.
- KeoSan/FCT는 인터페이스 제외로 논의됐으나 MES V1 로그파일 인터페이스 여부 때문에 재확인이 필요했다.
- 이후 현재 거산 Jig는 로그파일이 남지 않는다고 답변됐다.

- MES V2에서 BOX 포장 시 혼입 체크를 수행하려는 요구가 있다.
