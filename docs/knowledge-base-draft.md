## 보안/민감정보 처리 원칙

- 대화에 포함된 비밀번호, 개인 휴대폰 번호, 회의실 비밀번호, DB 계정 비밀번호 등은 지식베이스에 원문 저장하지 않는다.
- IP, 서버 주소, 포트 등은 프로젝트 맥락상 필요한 경우만 남기되, 실제 운영 접근정보는 별도 보안 저장소에서 관리해야 한다.
- 공유 링크는 업무 산출물 위치 식별 목적으로 남기지만, 접근권한은 SharePoint/사내 계정 정책을 따른다.

## 프로젝트/운영 맥락

- 대상 프로젝트는 MES V2이며, 베트남 법인 ERP/MES 인터페이스와 환경 셋업, 테스트, 출하/운송 일정이 포함된다.

- 맥큐브 담당 범위로 L4, DB, AP, Storage, Synology 설치가 언급되었다.

## 품목/자재 유형 및 업무 정의

- 베트남 스페어파츠 입고 시 품목 유형 확인 이슈가 있었다.

  - `1`: 제품

  - `4`: 상품
- 소모품/스페어파트는 비용 처리 대상이며 수불을 타지 않는 것으로 공유됨.

  - `4`: 상품
- CP1/CP2 정의:
  - `CP1`: 사용 후 잔여물이 남지 않는 소모품. 예: 알코올, 접착제, 접착 테이프.
  - `CP2`: 사용 후 잔여물이 남는 소모품. 예: 스텐실, Skinning Knife.
  - 비용 처리 차이는 없고 관행상 정산 보고서 작성 및 스크랩 처리 방식 차이에 가까움.

## 창고/로케이터 정책

- 베트남 ERP는 창고와 로케이터를 분리해서 관리한다.
  - 예: 창고 `110`, 로케이터 `E01`.
- ERP에는 로케이터 ID 값이 별도로 존재한다.
- 작업지시에서 완료창고가 내려올 때 창고와 로케이터 분리가 필요하다고 결정됨.
- 고객사 창고:
  - `[Ky gui]`는 500번대 창고로 확인.
  - 500번대는 고객사 창고이며, 출하 후 재고관리 창고 성격.
- `[WH]`는 창고로 번역되며 `[Ky gui]`와 용도 구분 필요.

## WBS Master 요구사항/변경 이력

### WBS 데이터 반영

- WBS는 엑셀 기준으로 전체 설정되었고, 간트와 상세보기 변경 기능을 추가해 빠르게 수정할 수 있게 됨.
- WBS Master 웹 화면과 엑셀 진도율이 다르게 보이는 이슈가 있었다.
- 엑셀의 일부 진도율/지연율은 계산식 기반이므로 웹과 직접 비교 시 기준 차이가 발생할 수 있다.
- WBS 마스터를 엑셀로 일괄 업데이트할 수 있는지 검토 요청이 있었다.

### 완료/지연 표시 정책

- WBS에서 `100%`가 완료를 의미한다.
- 지연일수는 완료 여부와 별개로 계획 대비 실제 완료일 또는 현재일 기준으로 산정된다.
- 사용자가 `100%`인데 지연으로 표시되는 것을 혼동해, 완료 상태와 지연일을 분리해서 보여달라는 요구가 있었다.
- 반영된 표시 방향:
  - 상태 컬럼: 완료/진행중/대기 등 현재 상태 식별.
  - 지연일 컬럼: 지연 또는 선행 일수 별도 표시.
- 100% 달성 시 지연일수 기준:
  - 실제완료일 - 계획완료일.
- 100% 미달성 시 지연일수 기준:
  - 계획완료일 - 당일 기준으로 지연 판단.

### WBS 산출물 링크

- WBS 항목에 대한 산출물은 SharePoint 링크로 연결해야 한다는 요구가 있었다.
- 마일스톤 항목도 업데이트가 필요하다는 요청이 있었다.
- 잘못 이동된 WBS 항목을 원래 번호로 되돌리는 조작 이슈가 있었다.

### WBS 달성율 계산 기준

- 계획:
  - 기준: 말단 업무 각각의 시작일~종료일 대비 오늘 경과비율.
  - 산식: `Σ(가중치 × 말단 평균기간경과비율) / 100`.
- 실적:
  - 기준: 말단 업무 각각의 실제 진행률.
  - 산식: `Σ(가중치 × 말단 평균진행률) / 100`.
- 지연율:
  - 기준: 계획 - 실적.
  - 양수면 지연, 음수면 선행.
- 달성률:
  - 기준: `(실적 / 계획) × 100`.
  - 100% 이상이면 목표 달성.
- 주간 추이 표를 만들려면 매주 금요일 등 기준일에 스냅샷을 저장하는 이력 데이터가 필요하다는 논의가 있었다.

## 주간보고 기능 요구사항/버그 이력

- 주간보고는 금요일 16시까지 작성하는 운영 기준이 공유됨.
- 특이사항이 없으면 1장만 작성해도 되는 방향.
- 주간보고 양식은 빠른 작성이 가능하도록 임의 조정되었고, 항목별 진척률 입력은 시간이 많이 걸린다는 의견이 있었다.
- 사용자별로 주간보고가 관리되도록 변경됨.
- 내가 주간보고를 작성하지 않으면 다른 사람 주간보고가 보이지 않는 문제가 있었고, 작성 여부와 관계없이 조회 가능하도록 수정 필요가 확인됨.
- 다른 사용자의 주간보고가 내 작성 화면에 보이거나 수정 가능한 캐시/권한 문제가 있었다.
- 속도 개선을 위해 걸어둔 캐시가 다른 사용자의 데이터를 불러오는 원인이 되었고 수정/배포됨.
- 제출 완료 후 수정 불가, 제출 취소 후 수정 가능 정책이 정리됨.
- 삭제 시 확인 컨펌 창을 띄우도록 수정.
- 전주 계획 자동 로딩 기능:
  - 전주에 “금주 하겠다”고 작성한 항목을 금주 보고에서 불러와 진행상황을 입력하게 하는 의도.

- 식당 추천, 개인 휴가, 잡담, 주류 투표, 부동산 링크 등 업무 지식베이스와 직접 관련 없는 내용은 최종본에서 제외한다.
- 삭제된 메시지는 내용이 없으므로 반영하지 않는다.
- 반복된 SharePoint 공지와 회의 참석 안내는 중복 제거하고, 실제 자료 위치 또는 결정사항만 남긴다.

## 조직/법인/재고 관리 기준

- `ORG` 또는 `OU`는 `ORGANIZATION`의 상위 개념으로 설명됨.
- 재고 관리는 `ORGANIZATION` 아래 창고가 있으므로 `ORGANIZATION` 기준으로 관리해야 한다는 의견.
- MES 내부적으로는 `ORGANIZATION_ID`를 관리하고 이 값으로 조회하는 방식이 성능상 유리하다고 판단되어 `ORGANIZATION_CODE` 추가 요청 일부는 취소됨.

## ERP 작업지시 취소 방지/MES 상태 연계

- 요구사항: MES 작업지시가 START 되면 ERP에서 작업지시를 취소하지 못하게 해야 함.
- 기존 HS2 ORG에 적용되어 있을 것으로 언급됨.
- ERP는 `xwip_mes_status` 테이블을 체크함.
- MES는 해당 테이블에 작업 상태를 전달해야 함.
- 주석상 MES 작업상태 관리용이며 MES에서 패키지를 호출해 사용한다고 되어 있음.
- 직접 INSERT가 아니라 `xwip_mes_status_pkg.insert_row` 프로시저를 사용할 것으로 공유됨.
- 프로시저 파라미터:

```sql
PROCEDURE insert_row
(
  o_errmsg          OUT NOCOPY VARCHAR2,
  o_errtag          OUT NOCOPY NUMBER,
  p_organization_id IN         NUMBER,
  p_wip_entity_name IN         VARCHAR2,
  p_mes_status      IN         VARCHAR2,
  p_attribute1      IN         VARCHAR2 DEFAULT NULL,
  p_attribute2      IN         VARCHAR2 DEFAULT NULL,
  p_attribute3      IN         VARCHAR2 DEFAULT NULL,
  p_attribute4      IN         VARCHAR2 DEFAULT NULL,
  p_attribute5      IN         VARCHAR2 DEFAULT NULL
);
```

## 환경 반영 정책

- 뷰 컬럼 추가처럼 단순 제공 뷰는 운영/DEV/TFT에 동시에 반영 가능한 것으로 공유됨.
- 받는 업무나 프로시저 로직 등 프로그램 수정이 필요한 항목은 DEV 테스트 후 PROD 반영이 원칙.
